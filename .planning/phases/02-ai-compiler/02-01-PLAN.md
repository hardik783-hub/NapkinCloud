# Plan 02-01: Graph Topology Validator & Bedrock Intent Normalizer

## Objective
Build the backend topology validator to enforce supported P0 architectures and the Amazon Bedrock intent normalizer (using Claude 3.5 Sonnet) that translates natural-language logic into a strict, validated architecture schema with an automatic zero-fail fallback mode.

## Code Patterns (Model Resilience)
Conventions:
- Type definitions: `src/types/compiler.ts` defining `NormalizedArchitecture`, `ValidationResult`, and compiler contracts
- Bedrock invocation: `@aws-sdk/client-bedrock-runtime` with ConverseCommand / InvokeModelCommand
- Fallback pattern: Graceful error trapping in `src/lib/bedrock.ts` that automatically falls back to deterministic rule-based parsing if AWS credentials or network fail

  <files>src/types/compiler.ts</files>

<task type="auto">
  <name>Implement Graph Topology Validator</name>
  <files>src/lib/validator.ts</files>
  <action>
    1. Create `validateGraphTopology(nodes, edges)`:
       - Validates exactly one `api_gateway` node.
       - Validates exactly one `lambda` node.
       - Validates exactly one `dynamodb` node.
       - Verifies directed edge `api_gateway -> lambda` exists.
       - Verifies directed edge `lambda -> dynamodb` exists.
       - Checks for orphan nodes, cycles, and unsupported types.
       - Returns `{ valid: boolean, errors: string[], normalizedNodes?: { api, lambda, dynamodb } }`.
  </action>
  <verify>npm run build</verify>
  <done>Validator accurately checks and extracts P0 pipeline components</done>
</task>

<task type="auto">
  <name>Build Amazon Bedrock Intent Normalizer with Fallback</name>
  <files>src/lib/bedrock.ts</files>
  <action>
    1. Create `normalizeIntentWithBedrock(graphData)`:
       - Checks for `process.env.AWS_REGION`, `AWS_ACCESS_KEY_ID`.
       - If credentials exist, calls Bedrock Claude 3.5 Sonnet (`anthropic.claude-3-5-sonnet-20240620-v1:0`) with system prompt enforcing strict JSON output for business logic extraction.
       - If credentials are missing or Bedrock call fails, smoothly catches the error and activates the deterministic fallback parser:
         - Derives sanitized resource names from user inputs.
         - Produces clean default DynamoDB PutItem logic.
       - Returns `NormalizedArchitecture`.
  </action>
  <verify>npm run build</verify>
  <done>Bedrock normalizer runs reliably with zero-fail fallback guarantee</done>
</task>
